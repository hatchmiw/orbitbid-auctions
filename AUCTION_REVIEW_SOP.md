# OrbitBid auction review SOP v2

**Purpose:** finish the user-approved review of every lot without duplicate work, invented prices, unnecessary files or stopping at checkpoints. This is the universal procedure; auction-specific IDs, artifact maps, scope and exceptions belong in `auctions/<id>/REVIEW.md`.

## 1. Scope and preflight
Read this SOP, `AGENTS.md`, root `README.md`, the auction's current `REVIEW.md`, the master catalog and the relevant acquisition/recovery workflow. Establish the user's requested deliverable and scope before starting: full review means **every lot and every original photograph**, followed by evidence-first pricing when requested. Record the expected lot count, distinct already-completed IDs, missing photos, outstanding research and source artifact coverage. **The master catalog is the sole editable per-lot assessment record.** Batch reports are supporting historical evidence, not an alternate completion ledger. Do not repeat completed inspections; reconcile existing findings first.

## 2. Original photographs
Reuse the existing temporary GitHub Actions artifacts first. Verify artifact availability, expiration, lot IDs, source URLs, manifest and original image counts. Download ZIPs using GitHub `download_workflow_artifact`; extract exact lot originals and visually inspect **each numbered original JPG separately**. Contact sheets are useful for triage but never count as individual-original inspection. The connector has a 512 MiB single-artifact download limit: reuse existing smaller split artifacts or split the already-mirrored full archive with the documented artifact-only recovery workflow. Only if existing artifacts cannot provide the required originals should source photos be rebuilt, and then only for missing coverage. Never commit JPGs, contact sheets or ZIPs to Git. If no documented recovery works, report the exact blocker and seek approval before changing the storage or retrieval method.

## 3. Per-lot inspection
For every pictured lot record the exact lot ID, expected/seen original-photo count, item identity, quantity, visible brands and model numbers, components, visible defects, missing items, uncertainties, testing needs, pickup/transport and safety concerns. Distinguish visible appearance from verified operation. Explicitly mark no-photo lots as catalog-only. Record photo evidence in the master `photo_findings` and a controlled `photo_review_status`. A status claim must be supported by a matching original-image count and retained inspection findings. Never infer full inspection from filenames, artifacts, workflow success, prior assistant claims or contact sheets.

## 4. Evidence-first pricing
Research each lot according to the approved scope; start with the highest-priority items but continue through all required lots. Use matching dated **completed-sale** sources and record exact item/part number, condition, quantity, venue, sale date, URL and relevant differences. Asking listings, MSRP, unrelated models and undisclosed accepted offers are context, not verified sale prices. Separately calculate conditional gross resale ranges and maximum hammer bids after buyer premium, taxes, fees, pickup, repairs, resale costs, time and margin. Unknown function and safety-critical defects require explicit contingencies. Where evidence is inadequate, document the attempt and leave active price and bid ceiling blank. Preserve earlier heuristic estimates only in clearly marked historical/unverified fields.

## 5. Save without stopping
After every 20 **newly completed** lots, or sooner to prevent loss, merge by exact lot ID into the master, regenerate derived reports, validate the catalog and commit **text/metadata only**. Then **immediately proceed** to the next incomplete lot; a commit, batch, status message or workflow run is never the stopping condition. Do not create extra checkpoint reports or redesign workflows during routine execution. The stopping condition is the requested review's verified completion, except for a real tool/execution limit or blocker. Do not imply that work continues in the background when no actual external workflow is running.

## 6. Validation and recovery
Before every master commit verify expected row count and unique IDs, required columns, valid CSV serialization, source-photo coverage, supported inspection states, evidence-gated active valuations and no lost prior findings. Generate watchlists, queues and current status **only from the master**. On interruption, record one concise checkpoint in the auction's `REVIEW.md`: last newly completed lot, next unfinished lot and original photo, remaining lot count, outstanding pricing, artifact/run ID and actual blocker. On resumption compare the checkpoint to master records; master evidence wins. Archive stale reports only after reconciliation, never discard useful research or original source URLs.

## 7. Completion
Verify every catalog lot is accounted for, every pictured lot has the requested original-photo coverage, every required lot has a documented research result (including evidence-insufficient where applicable), all generated views are current, and integrity checks pass. Report clearly which requirements were met and any unresolved limitations. An initial contact-sheet review or a completed catalog import is **not** a completed full review.

## Change control
The normal workflow is frozen during an active review. Modify it only to resolve a demonstrated technical defect or with the user's approval. Maintain one universal SOP and one auction-specific current status; move incident histories and old instructions to archive instead of appending contradictory addenda.
